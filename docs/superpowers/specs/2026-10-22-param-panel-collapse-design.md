# 参数面板收纳：图纸 + 高级设置两区

## 背景与目标

参数面板从最初的「网格 + 去背景」一路加了采样模式、颜色预算等控件，现在桌面端从上到下排了 10 个控件，一眼望去全是开关，核心信息（板子尺寸、网格、豆子数）被淹没。目标是**默认清爽**：把不常用的选项收进可折叠的「高级设置」，只露出每次都要用的尺寸与网格。

本次只做收纳，**不改任何算法、不合并控件、不新增状态**。所有开关的值、含义、触发重算的行为都与现状完全一致。

## 已确认需求

- 桌面 `ParamPanel`：快捷板子尺寸、网格大小滑杆、豆子数统计行保持展开；其余六项（采样模式、自动去背景、紧裁边缘、自动简化颜色、添加水印、颜色预算）收进「高级设置」，**默认收起**。
- 移动端 `MobileActionBar` 的生成参数 sheet：快捷尺寸 + 网格滑杆 + 数值保持展开；同样六项收进一个「高级选项」折叠块，默认收起。
- 折叠用**原生 `<details>/<summary>`**：零 JS、键盘与读屏天然可用，与项目里用原生 radio 的风格一致。
- 折叠头显示**摘要行**，收起时也能看到已开了什么：
  - 自动去背景开 → 「去背景」
  - 自动简化颜色开 → 「简化颜色」
  - 添加水印开 → 「水印」
  - 颜色预算非「不限」→ 「N 色」
  - 采样模式为「同步相近色」→ 「同步相近色」（「渐变色」是默认，不显示）
  - 示例：`高级设置 · 已开：去背景 · 简化颜色 · 水印 · 20 色`
  - 一项都没开时只显示标题，不带「已开」。
- 摘要从现有 props 推导，不引入新状态、不触发重算。

## 界面结构

### 桌面（ParamPanel）

```text
┌ 参数面板 ─────────────────────────────┐
│ 快捷板子尺寸（78×78 / 100×100 …）        │ ← 始终展开
│ 网格大小（滑杆 + 刻度 + 数值）            │
│ 5,079 颗（100×100=10,000 格 · 约 8.5 小时）│
│ 推荐 20-100 档位                        │
├─ 高级设置 · 已开：去背景 · 简化颜色…  ▾ ──┤ ← 默认收起，点击展开
│   采样模式（渐变色 / 同步相近色）          │
│   自动去背景                             │
│   紧裁边缘                              │
│   自动简化颜色                           │
│   添加水印                              │
│   颜色预算（不限 / 6 / 12 / 20 色）       │
└────────────────────────────────────────┘
```

### 移动端（MobileActionBar sheet）

```text
┌ 生成参数 ────────────────────────────┐
│ 快捷板子尺寸（一行按钮）                │ ← 始终展开
│ 网格 ───────●────── 100               │
├─ 高级选项 · 已开：去背景 · 20 色   ▾ ────┤ ← 默认收起
│   采样模式（渐变色 / 同步相近色）        │
│   自动去纯色背景                        │
│   紧裁边缘                            │
│   自动简化颜色                         │
│   添加水印                            │
│   颜色预算（不限 / 6 / 12 / 20 色）     │
└──────────────────────────────────────┘
```

## 组件与接口变更

- `ParamPanel.tsx`：把六项控件包进一个 `<details className="advanced-settings">`，`<summary>` 里渲染「高级设置」标题 + 摘要行。摘要由组件内部从 props 推导，**props 与回调签名不变**，`App.tsx` 不需要改。
- `MobileActionBar.tsx`：sheet 内同样加一个 `<details>`，摘要逻辑与桌面一致。props 不变。
- 两个 CSS 增加折叠区与摘要的样式（对齐现有设计变量）。
- 无 `types.ts`、无 pipeline、无 hooks 改动。

## 摘要推导规则

按固定顺序拼接启用项，用「 · 」分隔：

1. `removeBackground` → 「去背景」
2. `simplifyColors` → 「简化颜色」
3. `watermark` → 「水印」
4. `colorBudget !== 'off'` → 对应档位文案（不限→不显示，minimal→6 色，relaxed→12 色，standard→20 色）
5. `sampleMode === 'similar'` → 「同步相近色」

`watermark` 默认开：桌面与移动端摘要默认都会出现「水印」。

## 测试与验收

### 组件测试

- 默认：高级区收起，六项控件不可见（`details` 未打开），核心区可见。
- 点击 `summary` 展开后：六项控件全部可见。
- 摘要文案：按 props 组合正确显示；全部默认关闭时只有标题、不带「已开」。
- 现有断言调整：依赖可见性的检查（4 个 checkbox、水印排在简化颜色之后、采样模式 radio 等）需要先展开再断言。
- 移动端 sheet：同样默认收起、展开后六项齐全、摘要正确。
- 交互行为（开关触发回调、触发重算）不变，原断言保持。

### 验收标准

- 类型检查、相关组件测试、全量测试、生产构建通过。
- 桌面默认打开时只显示：板子尺寸、网格滑杆、豆子统计、提示、一行高级设置摘要。
- 展开高级设置后所有控件可用，行为与改动前一致。
- 移动端 sheet 默认打开时同理清爽。

## 非目标

- 不合并任何控件（简化颜色与颜色预算保持两个独立控件）。
- 不调整控件在折叠区内的顺序（沿用现状）。
- 不记忆展开/收起状态（每次加载默认收起）。
- 不改任何算法、不引入依赖。
