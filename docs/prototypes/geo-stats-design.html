展示设计稿 · 可交互原型，模拟真实数据形态（站主视角：广东为主，杭州有一波自然流量）
1概览卡把「外部 / 内部」直接并列，而不是把旧 UV 拆开放进二级面板。需求是「分不清是不是我自己」，答案必须在第一眼。外部用主色橙、内部用中性灰，视觉权重天然区分，不需要读文字就知道哪个是主角。
2旧卡片保留但加口径提示。不改动原有 /api/statics/summary 行为，只在 UV 卡下面加一行「含内部访问，看下方拆分」，避免两个口径的数字打架。
3「排除我的访问」默认开启。因为用户每次打开后台想问的就是「外面的人有没有变多」。关掉它可以看全量，但那是次要场景。
4「标记我的访问」是可选项而非前置。主要判定靠登录 Cookie；指纹只是补「退出登录 / 换设备」的场景。IP 由后端从请求里取，浏览器永远碰不到。
5覆盖率如实写出来。老数据和库未覆盖的 IP 永远补不回来，藏起来只会让人误判「流量都在广东」。未归属量单独成桶，不伪装成某个省份。
6方块地图 + 排行榜左右分栏，互为索引。地图给空间直觉但精确度低，排行给数字但没有形状。点省份只换右栏内容、不跳页，保持上下文，避免「点进去忘了自己在看什么」。
7等面积方块，不画真实省界。个人站的量级看不出省界形状差异，用户要的是排序不是空间；真实多边形要 1MB GeoJSON + 图表库，不值。也不会被「四川比海南大 8 倍」误导。
9本原型的核心演示场景：广东总 PV 268 看着最高，但外部只有 58。因为剩下 210 PV 全是站主自己在广东 IP 上调试产生的。没有自我访问拆分，「广东是最大的流量来源」是一个会把你带偏的结论；有了拆分，一眼就看出广东是自己人。
8趋势堆叠柱：外部在下（主色）、内部在上（灰）。一眼看出每天的构成，而不是两条线要对照着看。三种口径切换，默认「外部」，与概览卡默认一致。
